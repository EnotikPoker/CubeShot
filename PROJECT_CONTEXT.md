## Замысел и границы текущей работы

CubeShot — будущая мультиплеерная **2D-игра на C++**, в которой два
игрока-квадрата находятся на общей арене с платформами, ходят, прыгают и
используют оружие. Начальное оружие задумано как пистолет с одиночными
выстрелами. Графическая библиотека — **SDL3**.

Пользователь хочет развивать игру постепенно и явно ограничивал объём
каждого этапа. Описание будущей игры не означает поручение немедленно
реализовать весь мультиплеер или оружие. В последнем из трёх разговоров
запрошены прыжок с физикой, платформа для его проверки и ведение версий;
эти задачи выполнены. Следующая игровая задача пока не выбрана.

Общая игровая логика не зависит от SDL, окна, клавиатуры или отрисовки.
Клиент, сервер и тесты должны иметь возможность использовать один модуль
правил. Наличие отдельных целей клиента и сервера ещё не означает работающую
клиент-серверную игру.

## Архитектура

### Сборка и модули

- **C++17**, без расширений компилятора; **CMake ≥ 3.16**.
- `cubeshot_game`: статическая библиотека из `Arena.cpp`, `Collision.cpp`,
  `Player.cpp`, `Weapon.cpp`, `World.cpp`; публичный каталог заголовков — `src/`.
- `cubeshot_network`: интерфейсная цель с каталогом `src/`, без сетевой реализации.
- `cubeshot_client`: `main.cpp`, `Application.cpp`, `Input.cpp`,
  `SceneRenderer.cpp`; связывается с двумя общими модулями и `SDL3::SDL3`.
- `cubeshot_server`: отдельный `main.cpp`, связывается с общими модулями,
  но пока только печатает сообщение и завершается.
- `cubeshot_game_tests`: связывается только с игровой библиотекой;
  зарегистрирован в CTest как один тест `game`, содержащий несколько сценариев.
- SDL3 подключена через `find_package(SDL3 3.2 REQUIRED CONFIG)`.
  SDL2 не подходит. Сервер и тесты не линкуются с SDL, однако текущая корневая
  конфигурация CMake всё равно требует установленную SDL3: отдельной опции
  отключить сборку клиента нет.
- Исполняемые файлы помещаются в `build/bin/`; артефакты сборки исключены из Git.

### Поток данных и обновление

```text
Клавиатура SDL → Input → PlayerInput → World::setPlayerInput(id, input)
                                               ↓
                             World::update → Player → Collision / Weapon
                                               ↓
                                  SceneRenderer читает World → SDL
```

`World` создаёт одного локального игрока с ID **1** в первой точке появления.
Вектор пуль пуст. Ввод для неизвестного ID игнорируется; горизонтальное
направление сохраняется до следующего ввода.

Клиент использует накопитель времени и фиксированный шаг **1/120 с**,
отдельный от отрисовки. В накопитель добавляется не более **0,1 с** за кадр;
после отрисовки выполняется `SDL_Delay(16)`. Сам `Player::update` также делит
длительные обновления на шаги не более 1/120 с. Нулевое и отрицательное время
не меняют игрока и не расходуют ожидающий запрос прыжка.

В каждом подшаге сначала обрабатывается движение по X, затем к вертикальной
скорости прибавляется гравитация, после чего выполняется движение по Y.
При вертикальном столкновении вертикальная скорость обнуляется. Опора
определяется остановкой движения вниз; удар головой опорой не считается.

Прыжок запрашивается новым нажатием, а не удержанием кнопки; запрос сохраняется
между вызовами `applyInput` до ближайшего положительного обновления физики.
Прыжок разрешён только с опоры; нажатие в воздухе не создаёт второй прыжок
и не сохраняется до будущего приземления. Тест короткого нажатия проверяет
передачу `PlayerInput` между шагами: клиент сам опрашивает текущее состояние
клавиатуры, а не хранит очередь всех событий нажатия.

Коллизии проверяют путь перемещения по каждой оси, чтобы не пропускать тонкие
преграды. Касание края само по себе не считается пересечением. Начальное
положение тела должно быть свободно от пересечений; общего исправления
уже пересекающихся объектов нет. Платформы твёрдые со всех сторон.

## Текущее состояние игры и управление

| Параметр | Значение |
| --- | --- |
| Окно и арена | 960 × 540; логическая отрисовка SDL с сохранением пропорций (`LETTERBOX`) |
| Персонаж | Один синий квадрат 48 × 48, здоровье 100; урон пока не применяется |
| Пол | Позиция (0, 440), размер 960 × 100 |
| Тестовая платформа | Позиция (620, 350), размер 200 × 24; верх на 90 пикселей выше пола |
| Точка появления | (456, 392), на полу |
| Скорость ходьбы | 280 пикселей/с, мгновенная смена скорости без разгона |
| Скорость прыжка | 620 пикселей/с вверх, то есть начальная `velocity.y = -620` |
| Гравитация | 1800 пикселей/с² вниз; высота прыжка около 104 пикселей |
| Заготовка оружия | Урон 10, скорость пули 600 пикселей/с, интервал 0,25 с; это поля данных, а не работающий пистолет |

- **A / ←** — влево; **D / →** — вправо. Используются физические клавиши,
  управление работает при русской раскладке. Противоположные направления
  взаимно отменяются; отпускание клавиш останавливает движение по X.
- **Пробел** — прыжок с пола или платформы. Для повторного прыжка нужно
  отпустить кнопку и нажать заново после приземления. Управление по X
  сохраняется в воздухе; сход с края платформы вызывает падение.
- Потеря фокуса окна сбрасывает ввод и прекращает движение по X, но не физику.
- Завершение клиента — кнопкой закрытия окна; отдельная клавиша выхода не задана.
- Проверка платформы: из точки появления нажать **D + пробел**, идти вправо
  примерно полсекунды и отпустить D, чтобы приземлиться на платформу.

## Сборка и запуск

Нужны компилятор C++17, CMake ≥ 3.16, Make или Ninja и установленная SDL3 ≥ 3.2
с заголовками и `SDL3Config.cmake`. Из корня проекта:

```bash
cmake -S . -B build
cmake --build build
(cd build && ctest --output-on-failure)
./build/bin/cubeshot_client
```

Если SDL3 не найдена, при конфигурации указать
`-DCMAKE_PREFIX_PATH=/путь/к/SDL3`. Для отключения тестов —
`-DBUILD_TESTING=OFF`. Клиенту нужна графическая сессия; запуск сервера для
текущей игры не требуется. Заглушка: `./build/bin/cubeshot_server`.
Для генератора с несколькими конфигурациями передавать `--config Debug`;
программы будут в `build/bin/Debug/` (на Windows с `.exe`).
