# Интернет-режим 0.8.0

Клиенты Linux и Windows подключаются к общему VPS по IPv4/UDP. Проброс портов
на компьютерах игроков не требуется. LAN использует прежние UDP27015/27016.
Интернет — отдельный пул на UDP27020/27021; HTTPS-каталог не передаёт игровые
пакеты. Два свободных сервера дают максимум две одновременные дуэли / 4 игрока.

## Локальный стенд без VPS

После обычной сборки запустите в отдельных окнах:

```bash
./build/bin/cubeshot_online_server
./build/bin/cubeshot_client --directory-url http://127.0.0.1:8080
./build/bin/cubeshot_client --directory-url http://127.0.0.1:8080
```

В Windows используйте программы из `build/bin/Release/` с `.exe`.
В обоих клиентах: «Играть → Мультиплеер», при желании «Ник игрока», затем
«Быстрый матч» либо один и тот же сервер из списка. Оба нажимают «Готов».
Пустой ник при сохранении становится «Игрок». Поддерживаются до16 букв
кириллицы/латиницы, цифры, пробел, `_` и `-`; ники не уникальны.
Ctrl-A очищает поле, Ctrl-V вставляет текст, Backspace удаляет целую букву.
Неподдерживаемые символы и превышение лимита не добавляются.

Адрес можно задать через `CUBESHOT_DIRECTORY_URL`, аргументом
`--directory-url` (имеет приоритет) или `directory_url` в `profile.json`.
Профиль находится в каталоге SDL_GetPrefPath("CubeShot", "CubeShot"):
на Linux обычно `~/.local/share/CubeShot/CubeShot/profile.json`, на Windows
обычно `%APPDATA%/CubeShot/CubeShot/profile.json`. Ник сохраняется кнопкой
«Сохранить»; вместе с ним сохраняется выбранный адрес. Повреждённый профиль
игнорируется. Без адреса сервис обозначен как ненастроенный; LAN/Тест доступны.
Обычный HTTP разрешён только для `127.0.0.1:порт`; публичный адрес требует HTTPS.

## Подготовка VPS Ubuntu 24.04 x64

VPS и домен пока отсутствуют. Следующие команды — инструкция для будущего
развёртывания, на удалённом сервере в рамках разработки они не выполнялись.

1. Установите зависимости сборки и Caddy:

   ```bash
   sudo apt-get update
   sudo apt-get install -y build-essential cmake git pkg-config libssl-dev \
     libprotobuf-dev protobuf-compiler ca-certificates caddy
   cmake -S . -B build-vps -DCMAKE_BUILD_TYPE=Release -DCUBESHOT_BUILD_CLIENT=OFF -DBUILD_TESTING=OFF
   cmake --build build-vps --parallel 2
   sudo cmake --install build-vps --prefix /opt/cubeshot
   ```

   Нативная сборка использует системные OpenSSL/Protobuf; HTTP0.59.0 и JSON3.12.0
   скачиваются с проверкой SHA256, если соответствующие CMake-пакеты отсутствуют.

2. Скопируйте `deploy/cubeshot-online.service` в `/etc/systemd/system/`.
   Создайте `/etc/cubeshot/online.env` по `deploy/online.env.example`, подставив
   **реальный публичный IPv4**. Программа запускается с DynamicUser, без root.
3. Направьте DNS A-запись собственного домена на VPS. В `deploy/Caddyfile`
   замените `play.example.org` на этот домен и установите файл как конфигурацию
   Caddy (обычно `/etc/caddy/Caddyfile`). Caddy получает/обновляет сертификат.
4. Разрешите на firewall VPS и у провайдера входящие TCP80/443 и UDP27020:27021;
   сохраните доступ SSH. API8080 слушает только loopback; наружу его не открывайте.
   `--trust-proxy` используйте только за приведённым Caddy, который перезаписывает
   заголовок IP клиента. Без него лимиты применяются к адресу HTTP-соединения.
5. Проверьте конфигурацию Caddy, перезагрузите службы:

   ```bash
   sudo caddy validate --config /etc/caddy/Caddyfile
   sudo systemctl daemon-reload
   sudo systemctl enable --now cubeshot-online
   sudo systemctl reload caddy
   ```

6. В клиенте задайте `--directory-url https://ВАШ_ДОМЕН`. Проверка сертификата
   и имени сервера включена; отключать её для публичного стенда не следует.

Состояние: `GET /v1/health` → `status: ok`, версия и номер протокола.
Журналы: `journalctl -u cubeshot-online`; токены в журнал игры не записываются.
При падении systemd перезапускает процесс; действующие матчи и бронирования
теряются. Постоянного хранилища, автоматического масштабирования и аккаунтов нет.
Обновление: остановить службу, установить новую сборку, запустить и проверить health.
Откат: установить предыдущую совместимую сборку и обновить клиентов той же версии.

## Каталог и бронирование

- `GET /v1/servers` — `protocol`, `version`, массив `servers`: `id`, `name`,
  `players`, `reserved`, `phase` (MatchPhase), `joinable`.
- `POST /v1/reservations` — JSON с `protocol:3`, `nickname`, `request_id`
  (случайные64 hex-символа), `server_id` (пустой для быстрого матча).
  Ответ200/201: `server_id`, `address`, `token`, `expires_in_ms`, `protocol`.
  Повтор одного request_id/IP не создаёт новое место; другой ник/сервер →409.
- `DELETE /v1/reservations/{token}` — отмена ещё не использованного места, 204.
  Повтор безопасен. Использованный токен не отключает уже вошедшего игрока.
- `GET /v1/health` — работоспособность процесса и версия протокола.

Бронирование10с, токен случайный256бит, одноразовый, привязан к арене, слоту
и нику. Просроченный, чужой, повторный токен или прямой вход без него отклоняется.
Быстрый матч сначала заполняет лобби с одним занятым/забронированным слотом,
затем пустое; полный пул возвращает409 `no_free_servers` без бесконечной очереди.
В начатый матч вход закрыт. Выход любого игрока отменяет матч без победы,
сбрасывает счёт и готовность; второй остаётся в лобби, арена доступна следующему.

API ограничивает тело4КиБ, очередь64, число HTTP workers2, запросы20/с на IP,
ожидающие бронирования4 на IP; карты лимитов/бронирований ограничены4096 записями.
Лимиты защищают память и обычные ошибочные запросы, не заменяют защиту VPS от DDoS.

## Проверки

`ctest --test-dir build --output-on-failure` включает `online`: реальный HTTP,
два независимых UDP-сервера, конкурентное бронирование, идемпотентность,
полный пул, отмена, TTL, повтор токена, ники, ready, пять попаданий и отмена матча.
Низкоуровневый `network` проверяет базовый RTT150мс + jitterдо30мс и потери5%.
Протокол3 несовместим со старыми клиентами; ошибка проверяется до допуска.

После появления VPS обязательно проверить два внешних подключения:
Linux↔Linux, Windows↔Windows, Linux↔Windows. Для каждой пары: список,
быстрый матч, выбор одинакового сервера, ники, обаReady, движение/прыжок/
прицел/пуля, раунды до5 побед, реванш, Esc без остановки соперника, потеря сети,
отмена поиска, освобождение места и возвращение в интернет-раздел.
Сертификат с недоверенным издателем/чужим именем должен отклоняться.
Локальный стенд и CI не подтверждают работу через интернет или firewall VPS.

Prediction скрывает задержку локального ввода, но сервер не откатывает мир
при обработке выстрела. При большом пинге возможны визуальные поправки пуль;
HP, попадания и счёт всегда определяет сервер. Reconnect прерванного матча нет.
