# CubeShot

2D-игра на C++17 и SDL3 с отдельным авторитетным сервером.

Текущая версия: **0.6.0**.

В **«Играть → Локальная игра»** доступна LAN-дуэль двух игроков на разных
компьютерах одной сети. Создайте комнату или найдите её в списке; если поиск
недоступен, введите IPv4 хозяина и порт. Сервер запускается автоматически
на компьютере хозяина. Оба участника нажимают «Готов» и после отсчёта
в 3 секунды играют до **5 побед в раундах**. Между раундами — 3 секунды;
стартовые стороны меняются, здоровье и оружие восстанавливаются, пули удаляются.
Одновременная смерть за один шаг даёт ничью без очков. Для реванша нужны
оба подтверждения. Выход или потеря связи отменяет матч без присуждения победы.

Арена **960 × 540**, два персонажа **48 × 48**, две симметричные платформы.
Максимум здоровья — **100**, урон пистолета — **20**. Мышь задаёт направление
пистолета и прицел-перекрестие; ЛКМ выпускает одну видимую баллистическую пулю
за нажатие. Движение, прыжок, прицеливание и стрельба работают одновременно.
Над персонажами видны полоски здоровья; свой игрок синий, соперник красный.

Временный **«Тест»** сохраняет прежнюю сцену с тремя неподвижными мишенями
и перезапуском на R. «Мультиплеер» (интернет), «Игра с ботами» и «Настройки»
пока являются заглушками. LAN здесь означает два компьютера в одной сети;
игра вдвоём на одной клавиатуре не реализована.

## История версий

При изменениях обновляются версия в CMake, текущая версия выше и история.
Каждая новая версия разрабатывается в отдельной ветке; прежние записи сохраняются.

### 0.6.0 — 2026-10-14

- Добавлены LAN-дуэль, автоматический поиск комнат, страницы списка и
  подключение по IPv4:порт; основной порт UDP 27015, поиск — UDP 27016.
- Хозяин запускает отдельный `cubeshot_server` через SDL3; при выходе
  процесс останавливается и освобождает порт. Сервер можно собрать без SDL.
- Добавлены лобби с готовностью, отсчёт, симметричная арена, раунды до пяти
  побед, смена сторон, ничьи и реванш по согласию обоих участников.
- Сервер вычисляет движение, попадания, здоровье и счёт. GameNetworkingSockets
  закреплена на 1.6.0; сообщения описаны Protobuf и проверяются при получении.
- Симуляция 120 Гц, ввод и снимки 60 Гц; прыжки и выстрелы передаются надёжно
  с номером действия и раунда. Снимки интерполируются с задержкой 33 мс.
- Esc в LAN открывает личное меню: матч продолжается, персонаж остаётся
  уязвимым. R работает только в «Тесте»; пауза тестовой сцены сохранена.
- Выход/таймаут участника отменяет матч и сбрасывает счёт. Неполучение
  непрерывного ввода 250 мс останавливает движение; таймаут соединения — 5 с.
- Добавлены тесты правил матча, протокола, реального UDP, поиска комнат,
  процесса сервера и сети с задержкой 100 мс и потерей 5% пакетов.
- Подготовлены vcpkg-манифест и CI сборки/тестирования на Linux и Windows.
  Проверки на двух реальных компьютерах описаны в `docs/LAN_TESTING.md`.

## Архитектура

| Модуль | Назначение |
| --- | --- |
| `src/game/` | Чистая игровая логика: сущности, физика, `World`, правила дуэли `Match` и `WorldSnapshot`; без SDL и сети |
| `src/network/` | Protobuf, проверка сообщений, GameNetworkingSockets, серверная/клиентская сессия и UDP discovery |
| `src/server/` | Самостоятельный сервер: цикл 120 Гц, подключение двух участников и объявления комнат |
| `src/client/` | SDL3, меню, ввод, серверный процесс и отрисовка снимков с ID собственного игрока |
| `tests/` | Игровые, графические, сетевые и интеграционные проверки |

В LAN поток данных: `Input → Client → Server → Match/World → Snapshot → Renderer`.
Клиент передаёт управление, а не позиции, здоровье или результат попадания.
В «Тесте» ввод по-прежнему поступает в локальный `World` с фиксированным шагом.
Объявления находятся в `.h`, реализации — в `.cpp`, протокол — в `.proto`.
Подробнее: [сетевой модуль](src/network/README.md).

Скорость персонажа — 280 пикселей/с, прыжок — 620 пикселей/с вверх,
гравитация — 1800 пикселей/с². Пуля: скорость 800 пикселей/с, гравитация
240 пикселей/с², радиус 3, время жизни 3 с, интервал выстрелов 0,25 с.
Проверяется весь путь пули, включая участок от руки до дула. Первое
столкновение с платформой или чужим живым игроком поглощает пулю.
Рикошетов, пробивания и столкновений тел игроков пока нет.

## Сборка

Нужны **CMake ≥ 3.21**, Git, C++17, **OpenSSL ≥ 1.1.1**, Protobuf с `protoc`
той же версии и, для клиента, **SDL3 ≥ 3.2**. GameNetworkingSockets 1.6.0
CMake скачивает по закреплённому коммиту при первой конфигурации.
Работа с LAN не требует Steam. Для кириллицы не нужны SDL_ttf и внешние шрифты.

### Linux

Если SDL3, OpenSSL и Protobuf уже установлены:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
```

Если Protobuf отсутствует, можно собрать **3.21.12** локально без установки
системных пакетов (потребуется Python 3):

```bash
python3 tools/bootstrap_protobuf.py
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="$PWD/build/_prefix"
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
```

Скрипт сохраняет исходники, `protoc`, библиотеки и заголовки в игнорируемом
`build/`. SDL3 и OpenSSL устанавливаются отдельно. Если SDL3 находится
в нестандартном месте, передайте оба префикса через `;` в `CMAKE_PREFIX_PATH`.

### Windows

Нужны Visual Studio 2022 с инструментами C++, CMake, Git и
[vcpkg](https://learn.microsoft.com/en-us/vcpkg/get_started/get-started).
В PowerShell после установки vcpkg:

```powershell
$env:VCPKG_ROOT = "C:/vcpkg"
cmake -S . -B build -A x64 `
  -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake" `
  -DVCPKG_TARGET_TRIPLET=x64-windows
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
.\build\bin\Release\cubeshot_client.exe
```

Манифест `vcpkg.json` закрепляет набор зависимостей и включает SDL3, OpenSSL
и Protobuf. DLL копируются рядом с программами. Клиент и сервер должны
оставаться в одном каталоге. Для переносимой сборки сохраните всю папку
`bin/Release`, включая DLL; Windows может также требовать VC++ Redistributable.
CI `.github/workflows/build.yml` собирает обе ОС, запускает тесты и сохраняет
программы как артефакты. В текущей среде подтверждены Linux-сборки;
результат Windows CI ещё нужно получить после отправки ветки.

### Сервер без SDL

```bash
cmake -S . -B build-server -DCUBESHOT_BUILD_CLIENT=OFF -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$PWD/build/_prefix"
cmake --build build-server --parallel 4
ctest --test-dir build-server --output-on-failure
./build-server/bin/cubeshot_server --port 27015
```

При сборке сервера через vcpkg добавьте
`-DVCPKG_MANIFEST_NO_DEFAULT_FEATURES=ON`, чтобы не устанавливать SDL3.
`--owner-token` предназначен для автоматического запуска хозяином;
обычный самостоятельный сервер принимает первых двух игроков в слоты 1 и 2.

## Запуск LAN

На Linux: `./build/bin/cubeshot_client`. На Windows — команда выше.

1. На первом компьютере откройте **«Играть → Локальная игра → Создать комнату»**.
2. На втором выберите **«Найти комнаты»** и нажмите доступную строку.
   Список обновляется каждые 2 с; исчезнувшие комнаты удаляются через 6 с.
3. Если поиск не сработал, выберите **«Ввести IP»**, введите IPv4 первого
   компьютера (например, `192.168.1.10:27015`) и нажмите «Подключиться».
   Порт можно опустить. Адрес LAN можно узнать через `hostname -I` на Linux
   или `ipconfig` на Windows. `127.0.0.1` подходит только для того же компьютера.
4. Оба нажмите **«Готов»**. Матч начинается после отсчёта 3 с.

Для LAN в настройках сетевого экрана разрешите входящий UDP **27015**
для сервера; поиск комнат использует UDP **27016**. При запрете broadcast
ручное подключение остаётся доступным. Изоляция клиентов Wi-Fi может мешать
обоим способам подключения. Для своей комнаты основной порт должен быть свободен.

При выходе гостя хозяин возвращается в лобби с нулевым счётом и может
принять нового игрока. При выходе хозяина его сервер закрывается, гость
возвращается в список комнат с сообщением. Разрыв соединения не приносит очков.

## Управление

В меню — мышь или **↑/↓ (W/S)** и **Enter**. Клик срабатывает при отпускании
над той же кнопкой; перетаскивание наружу отменяет действие. В форме IP —
ввод цифр, точек и двоеточия, **Backspace**, вставка через **Ctrl-V**.
**Esc** возвращается назад, отменяет подключение или выходит из лобби/результатов.

В игре:

- **A / ←**, **D / →** — движение влево/вправо. Противоположные кнопки останавливают.
- **Пробел** — один прыжок с опоры за нажатие; удержание не вызывает повторных прыжков.
- **Мышь** — прицел; при наведении влево оружие отражается зеркально.
- **ЛКМ** — одиночный выстрел. Удержание не стреляет; слишком ранний клик пропускается.
- **Esc** — личное меню LAN или настоящая пауза в «Тесте».
- **R** — перезапуск только «Теста», с восстановлением мишеней, здоровья и удалением пуль.

В LAN при открытом меню или потере фокуса своё управление прекращается,
но сервер продолжает матч: персонаж остаётся на арене и может погибнуть.
В «Тесте» пауза останавливает движение, гравитацию, пули и таймеры.
Кнопки меню не передаются в стрельбу; удерживаемые при входе/продолжении
пробел и ЛКМ требуется отпустить перед новым действием.
Управление использует физические клавиши и работает с русской раскладкой.

Если тачпад блокируется при удержании клавиш, проверьте системное отключение
при вводе текста (`disable-while-typing` в GNOME). Игра эту настройку не меняет.

## Дальнейшая работа

Интернет-режим: выделенный сервер на VPS, список серверов и быстрый матч
на общей инфраструктуре. Перед этим — предсказание движения и согласование
с сервером. Аккаунты, рейтинг и комнаты по коду не входят в первый этап.
Карты пока заданы в коде; ботам, настройкам, звукам и новым видам оружия
потребуются отдельные версии.

Проверки и ограничения текущей версии: [LAN_TESTING.md](docs/LAN_TESTING.md).
